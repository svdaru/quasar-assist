# Quasar Assist

Quasar Assist — интеграция Home Assistant. Она принимает запрос OpenAI Responses от Quasar Bridge 0.7.5 и передаёт последнюю фразу человека в выбранный конвейер Assist. Конвейер выполняет команду. Мост произносит ответ. Интеграция не вызывает внешнюю языковую модель, не пересылает исходный запрос и не выполняет инструменты моста.

English documentation: [README.md](README.md).

## Установка

Установите Quasar Assist из магазина Home Assistant.

1. Откройте магазин и добавьте свой репозиторий `https://github.com/svdaru/quasar-assist`.
2. Установите **Quasar Assist**.
3. При первой установке Home Assistant загружает интеграцию с config flow без перезапуска. Обновление уже загруженной интеграции требует перезапуск, который предлагает магазин.

Нужен Home Assistant 2026.3 или новее. С этой версии Home Assistant отдаёт локальный значок из `custom_components/quasar_assist/brand/`.

## Долгоживущий токен доступа

Мост входит долгоживущим токеном доступа Home Assistant. Создайте его в профиле пользователя и запишите в `QUASAR_LLM_API_KEY` на колонке. Оба адреса интеграции проверяют этот токен обычной проверкой Home Assistant (`requires_auth`). Отсутствующий или неизвестный токен отклоняется кодом HTTP 401 до кода интеграции.

Quasar Assist не заводит второй секрет, не хранит токен в записи и сам не читает заголовок `Authorization`.

## Настройка моста

Настройку моста эта интеграция не выполняет. Без неё колонка не пришлёт фразы.

У Quasar Bridge 0.7.5 один адрес модели на маршрут `llm`, планировщик `home` и классификатор. Интеграция отдаёт каждую последнюю фразу человека выбранному конвейеру Assist, поэтому на этот адрес направляйте только те фразы, которые должны стать командой Assist.

- Базовый адрес: `http://<home-assistant>:8123/api/quasar_assist/v1`
- Тип API: `responses` (`llm_api` остаётся `responses`)
- `llm_base_url` указывает на базовый адрес выше.
- `llm_model` — это `entry_id` нужной записи Quasar Assist. Установщик копирует его из поля `id` ответа `GET /api/quasar_assist/v1/models`. Если записи разные, у каждой колонки свой `llm_model`.
- `QUASAR_LLM_API_KEY` на колонке — долгоживущий токен доступа Home Assistant.

Пример маршрута для имени активации из этой настройки:

- Правило `starts_with_any` со значениями `львовна `, `львовна,`, `львовна.` отправляет фразу на маршрут `llm`. Правило видит фразу до того, как мост срежет обращение.
- Добавьте `львовна` в `llm_strip_prefixes` вместе с обращениями, которые уже нужны. Свой список заменяет стандартный целиком и начинает действовать после перезапуска моста. Мост передаёт остаток, например `включи свет`.
- Пока у моста один адрес модели, не отправляйте на этот URL планировщик `home`, классификатор и «спроси нейросеть». Им нужен прежний адрес модели.

## Удаление

В Home Assistant откройте Настройки, затем Устройства и службы, затем Quasar Assist, и удалите запись интеграции. Репозиторий можно убрать и из магазина. Удаление записи стирает состояние её диалога и repair, если он был открыт. Вне записи Home Assistant эта интеграция ничего не хранит.

## Параметры

### Параметры установки

Задаются при добавлении интеграции:

| Параметр | Обязателен | По умолчанию | Смысл |
| --- | --- | --- | --- |
| Конвейер Assist | да | нет | Уже настроенный конвейер Assist. Список не фильтруется. Свободного ввода идентификатора и значения по умолчанию нет, поэтому без конвейера запись не создаётся. Тот же конвейер можно выбрать снова; записи различает `entry_id`. |
| Срок диалога | нет | 90 секунд | Сколько `conversation_id` этой записи остаётся открытым после успешного ответа. |

Отдельный идентификатор не спрашивается. `entry_id` уже назначает Home Assistant.

### Параметры настройки

Те же два поля можно изменить позже, не удаляя запись. Следующая фраза уходит в новый конвейер и начинает новый диалог. Новый срок хранится у записи и ограничивает её таймер. `conversation_id` и время последнего успешного ответа живут в `runtime_data`, не в сохранённых настройках.

## Примеры

`POST /api/quasar_assist/v1/responses`, в `model` — идентификатор записи. В конвейер как `intent_input` уходит только последняя строка `user`. Запуск начинается и заканчивается на стадии намерения, поэтому распознавание речи и синтез этого конвейера не запускаются. Системный текст, прежние реплики, `tools`, `current_time` и `text.format` остаются в запросе и в запуск не копируются. Язык отдельно не передаётся: его берёт конвейер.

```json
{
  "model": "01JEXAMPLEENTRYIDBEDROOM",
  "input": [
    {"role": "system", "content": "Инструкции инструментов моста"},
    {"role": "user", "content": "включи свет"},
    {"role": "assistant", "content": "В какой комнате?"},
    {"role": "user", "content": "А в спальне"}
  ]
}
```

Успешный ответ — HTTP 200. Речь — обычный текст из события `intent-end` конвейера. Непустая речь — успех, даже если тип ответа ошибочный. Элемент `function_call` интеграция не добавляет.

```json
{
  "status": "completed",
  "output": [
    {
      "type": "message",
      "role": "assistant",
      "status": "completed",
      "content": [
        {"type": "output_text", "text": "Включила свет"}
      ]
    }
  ]
}
```

`GET /api/quasar_assist/v1/models` возвращает текущие записи Quasar Assist. `id` — это `entry_id`. `name` — название записи, а если названия нет — тот же `id`. Порядок по `id`. Конвейер не запускается, таймеры диалогов не меняются.

```json
{
  "data": [
    {"id": "01JEXAMPLEENTRYIDBEDROOM", "name": "Спальня"}
  ]
}
```

## Поддерживаемые функции

- Принимать `POST /api/quasar_assist/v1/responses` от Quasar Bridge 0.7.5.
- Передавать последнюю фразу `user` без изменений в конвейер Assist этой записи через `PipelineInput`, со стадиями начала и конца на намерении. Идентификатор диалога выбирает таймер записи.
- Возвращать речь `intent-end` завершённым сообщением, в том числе когда тип ответа ошибочный, а речь не пустая.
- Отдавать записи на `GET /api/quasar_assist/v1/models`, не запуская конвейер и не меняя таймеры.
- Держать отдельный таймер диалога у каждой записи. Срок по умолчанию — 90 секунд от последнего успешного ответа, каждый успех его продлевает.
- Менять конвейер и срок, не удаляя запись. Следующий вызов идёт в новый конвейер и начинает новый диалог.
- Поднимать repair, когда выбранный конвейер пропал, и один раз писать в журнал потерю и восстановление. Прежняя запись без идентификатора конвейера не стартует, пока конвейер не выберут заново.

## Сценарий

Человек говорит: «Алиса Львовна, включи свет». Споттер колонки забирает «Алиса». Quasar Bridge 0.7.5 видит «Львовна, включи свет», срезает «Львовна», потому что оно есть в `llm_strip_prefixes`, и отправляет «включи свет» в эту интеграцию. Выбранный конвейер Assist выполняет команду и возвращает речь. Мост её произносит. Следующая фраза той же записи, например «А в спальне» или «включи телевизор», продолжает тот же диалог, пока не истечёт таймер записи.

## Известные ограничения

- Только текст. Интеграция не принимает звук, не заменяет слово активации «Алиса» и не синтезирует речь. Колонка произносит текст через мост. Распознавание и синтез, настроенные у конвейера, не запускаются.
- Поддерживаемый клиент — Quasar Bridge 0.7.5. Интеграция не меняет мост, его правила маршрутизации и прошивку колонки.
- Нет исходящего вызова языковой модели, вызова MCP и выполнения `tools` моста.
- Продолжение диалога решает только таймер записи. Слова «да», «нет» и фраза с началом «а » сами диалог не начинают и не заканчивают.
- Интеграция не обрезает последнюю фразу. Если мост не срезал обращение, оно уходит в конвейер как пришло.
- Пустой массив `data` возвращается только когда записей нет. Quasar Bridge считает пустой каталог моделей ошибкой и не даст выбрать модель.
- У моста один адрес модели. Не направляйте на эту интеграцию планировщик `home`, классификатор и «спроси нейросеть».
- Язык отдельно не передаётся. Его берёт конвейер.
- Интеграция не привязывает колонку к устройству или спутнику Home Assistant.
- В манифесте нет ключа `quality_scale`. Интеграции магазина показываются как `custom`.

## Устранение неполадок

- **HTTP 401.** Долгоживущий токен отсутствует, истёк или не принят Home Assistant. Создайте новый токен и обновите `QUASAR_LLM_API_KEY`. Интеграция не пишет в журнал ни токен, ни заголовок `Authorization`.
- **Мост говорит, что запись не найдена.** `model` пуст, неизвестен или принадлежит другой интеграции. Откройте `GET /api/quasar_assist/v1/models` и скопируйте `id` в `llm_model`.
- **Короткий ответ говорит, что фраза пустая.** В запросе не было сообщения `user` или текст последнего `user` пуст. Конвейер не запускается, открытый диалог остаётся как был.
- **Короткий русский ответ говорит, что выполнить не удалось.** Выбранный конвейер пропал, конвейер вернул пустую речь или запуск сорвался. Диалог этой записи закрыт. Повторной отправки нет. Если конвейер удалили или запись осталась без идентификатора конвейера, Home Assistant показывает repair: откройте перенастройку и выберите конвейер. Потеря пишется в журнал один раз, восстановление — один раз.
- **Тело отклонено с HTTP 400.** Нет `input`, это не список, или содержимое последнего `user` не строка. Конвейер не запускается. Пустая строка `user` — не эта ошибка.
- **Колонка молчит.** Мост отвергает ответ с разметкой вызова инструментов. Интеграция возвращает только обычный `output_text` и не добавляет `function_call`.
